SUMMARY: I probed AmeriFlux live using only GET and HEAD requests. I made no POSTs, submitted no forms and sent no identity. I also read the source of amerifluxr (R, chuhousen/amerifluxr, last pushed 2025-11-03), fluxnet/shuttle (Python, fluxnet-shuttle) and the site's own JavaScript.

There is a public, unauthenticated JSON API on amfcdn.lbl.gov behind Cloudflare. It has no published OpenAPI or Swagger document: /docs, /openapi.json and /swagger all return 404. It has two versions:
- **v1** returns bare arrays with UPPERCASE keys. It is used by amerifluxr and the AmeriFlux website.
- **v2** returns `{"values":[...]}` with snake_case keys. It is used by fluxnet-shuttle.

The richest single endpoint is GET `/api/v2/site_info_display/AmeriFlux`. It returns 856 sites in 1.7 MB (248 KB gzipped). Each site carries PI and team (with emails), networks, IGBP, lat/lon/elevation, Köppen climate, MAT/MAP, status, data policy, BASE and FLUXNET DOIs, published years per product, and BASE variable names.

Data availability lives at GET `data_availability/{network}/{product}/{policy}` and `site_availability[/{network}[/{product}/{policy}]]`. The variable dictionary (145 FP-standard variables with units and min/max) is GET `fp_var?limits=True`.

These endpoints are POST-only (a GET returns 405) and I did not call them:
- `data_download`: issues download URLs. Body: user_id, user_email, site_ids[], data_product (BASE-BADM, BIF or FLUXNET), data_variant (SUBSET or FULLSET), data_policy (CCBY4.0 or LEGACY), intended_use, description, is_test.
- `citations/{AmeriFlux|FLUXNET|BIF}`
- `variable_availability`
- v2 `amf_shuttle_data_files_and_manifest` and `log_shuttle_data_request`

Download URLs are not signed. A real URL embedded in data.fluxnet.org looks like `https://ftp.fluxdata.org/.ameriflux_downloads/FLUXNET/AMF_US-Ha1_FLUXNET_1991-2025_v1.3_r1.zip?=fluxnetshuttle`. The `?=` suffix only tags the user. A HEAD on the URL with or without that suffix returns 200 with the same size and ETag, `cache-control: public, max-age=14400` and accept-ranges. The BASE path works the same way (`/.ameriflux_downloads/BASE-BADM/AMF_US-Ha1_BASE-BADM_28-5.zip` returned 200).

Logins: the website forces CC-BY-4.0 when the visitor is not logged in and then sends `user_id='friendlyfluxnetwork'` with an optional name and email. LEGACY downloads need a logged-in AmeriFlux account. The shuttle requests FLUXNET links with `user_id='fluxnetshuttle'` and no email.

Data the API does not serve:
- BADM/BIF metadata comes only as download zips (AA-Net for all sites, AA-Flx for sites with data, plus per-site BADM inside BASE-BADM zips).
- Per-variable, per-year coverage comes only from CSV snapshots in the amerifluxr GitHub repo, dated 2025-10-20.
- Measurement heights come from a dated CSV on ftp.fluxdata.org (BASE_MeasurementHeight_20260908.csv). The FTP directory listing that amerifluxr relies on timed out for me.

FLUXNET2015 and FLUXNET-CH4 site lists and availability are also served, under network=FLUXNET. fluxnet.org now sends downloads to the FLUXNET Shuttle (data.fluxnet.org, shuttle.fluxnet.org/v1), which brings together AmeriFlux (381), ICOS (350) and TERN (51) FLUXNET products.

I saw no rate-limit headers, and 20 back-to-back requests all returned 200. Every API response carries `Access-Control-Allow-Origin: *` and none has Cache-Control or an ETag. ameriflux.lbl.gov's robots.txt asks for Crawl-delay: 15.

- Policy strings differ between sources: the API uses 'CCBY4.0'/'LEGACY', and the site-search embedded JSON uses 'CC-BY-4.0'/'Legacy' (687/169). The server needs a normalization layer.
- The amerifluxr variable-availability snapshot covers Y1990-Y2025 only, while live BASE publish years reach 2026 (US-Ha1 BASE 28-5 has last-modified 2026-09-08, and its BIF xlsx and the measurement-height CSV are both dated 20260908). The snapshot is stale by at least one release cycle.
- Static zips carry Last-Modified headers (e.g. US-Ha1 FLUXNET 2026-03-29, BASE-BADM 2026-09-08). HEAD can therefore detect freshness and drive cache invalidation, alongside ETag.
- Secondary network membership is in grp_network: Phenocam 196, NEON 47, LTAR 41, Fluxnet-Canada 30, LTER 18, NY State Mesonet 18, MexFlux 16, UFLUX 16, LBA 8. This supports a network filter, and NEON co-location could cross-link with a NEON MCP.
- DataCite prefix 10.17190 holds 1020 DOIs, against 1017 (609+408) listed in site_info_display. A few DOIs, such as non-site or retired records, are not reachable from the site catalog.
- v1 site_display values are all strings (lat/lon/MAT/MAP), while v2 site_info_display has integer publish years and null tower_end. Type coercion is needed if both are merged.
- The website sends is_test=false only when window.location.hostname == 'ameriflux.lbl.gov'. Any third-party client must decide its is_test value explicitly.

=== TOPIC amf_products ===
SUMMARY: I researched AmeriFlux and FLUXNET data products using live HTTP GETs on 2026-10-22 against ameriflux.lbl.gov, amfcdn.lbl.gov (public GET APIs), fluxnet.org, data.fluxnet.org, DataCite, Europe PMC, and GitHub source code (chuhousen/amerifluxr, fluxnet/shuttle, fluxnet/ONEFlux). I did not POST to anything.

Main findings:
1. There are three current product families:
   - **AmeriFlux BASE-BADM.** Flux/met data at half-hourly (HH) or hourly (HR) resolution, plus BADM site metadata in BIF format. Versions look like X-Y (for example 28-5). Each site has a DOI.
   - **AmeriFlux FLUXNET**, now called "FLUXNET-1F". It is processed by ONEFlux v1.3 and versioned like "v1.3_r1". Zips are named `AMF_<SITE>_FLUXNET_<YS>-<YE>_v<maj.min>_r<N>.zip` and hold FLUXMET, ERA5, BIFVARINFO and BIF files at HH/DD/WW/MM/YY, plus a README and a license file.
   - **The FLUXNET Shuttle.** A federated system covering AmeriFlux, ICOS and TERN. Its GUI launched 2026-05-14 and its library is github.com/fluxnet/shuttle. It replaces FLUXNET2015, which fluxnet.org now labels "outdated".
2. FLUXNET2015 (FULLSET/SUBSET, Tier 1/2) and FLUXNET-CH4 V1 (HH/DD, Tier 1/2) are legacy releases with their own naming rules.
3. Variable rules apply to all products: base names (live list at https://amfcdn.lbl.gov/api/v1/fp_var), qualifiers in a fixed order (_PI, _QC, _F, _IU, then position _H_V_R or aggregation _H_V_A / _# / _SD / _N), missing value -9999, and local standard time without daylight saving (UTC offset comes from BADM UTC_OFFSET).
4. FLUXNET adds its own suffixes (_MDS, _ERA, _JSB, _VUT/_CUT, _REF/_USTAR50/_MEAN/_SE/_XX, _NT/_DT/_SR, _RANDUNC/_JOINTUNC, _CORR, _DAY/_NIGHT). Its units change with time resolution, and its QC flags are categories at HH and fractions at DD and coarser.
5. Data policy:
   - CC-BY-4.0 (revised Dec 2025) requires, for each site, a citation with DOI in the reference list and the DOE acknowledgment. FLUXNET use also needs the multi-network/ERA5 acknowledgment and a "Data Availability" statement giving the access date.
   - The Legacy policy adds contacting the PIs, crediting site funding, and telling providers before publication. Mixing Legacy and CC-BY data puts all the data under Legacy.
   - FLUXNET products exist only for CC-BY sites: 407 sites have FLUXNET years, the LEGACY FLUXNET availability is empty, and 687 sites are CC-BY versus 169 Legacy.
6. Citations: the AmeriFlux-recommended text includes the product version and differs from DataCite's own metadata (different year and publisher, no version). An MCP server must not generate citations from doi.org content negotiation.
7. Downloads: every data download goes through POST endpoints that need a user identity and an intended use. AMP sends the intended use to site PIs and posts it to a public download log.

- Never extract to disk blindly. Read zip members in memory with size caps and zip-bomb/path-traversal guards, and list members first.

- Map -9999 (and defensively -9999.0 and -9999.9) to null.

=== TOPIC fluxnet2015 ===
SUMMARY: I researched FLUXNET2015 live using GET and HEAD requests only, on 2026-10-22. I made no POSTs, submitted no forms and wrote no files.

**Status of the dataset.** FLUXNET2015 is now a frozen legacy product. fluxnet.org labels it "outdated" and sends users to the new FLUXNET Shuttle (data.fluxnet.org, github.com/fluxnet/shuttle) for current data. The official FLUXNET2015 download page (/data/download-historical-data/) is login-gated: a JavaScript redirect to /login/. The login is a WordPress form, and its "Create New Account" link goes to the AmeriFlux account system (amfcdn.lbl.gov/create). The policy says that each download collects an intended-use statement, which is emailed to the site PIs. There is no documented anonymous API or bulk URL for the data files.

**What is open without login.** All of the metadata is anonymously readable as JSON from the AmeriFlux API (amfcdn.lbl.gov):
- **Site list:** /api/v1/site_display/FLUXNET/FLUXNET2015 returns 212 sites.
- **Per-site year availability:** /api/v1/data_availability/FLUXNET/FLUXNET2015/{CCBY4.0|TIER2}.
- **Variable dictionaries:** official CSVs on ftp.fluxdata.org. FULLSET lists about 232 variable entries and SUBSET about 72.
- **Per-site DOIs:** 212 DOIs under the 10.18140/FLX prefix, readable through the DataCite and OSTI APIs.
- **Citation files:** the reference paper's .bib and .ris files.

**Dataset facts.**
- 212 sites, data from 1991 to 2014.
- 1532 site-years in total under Tier 2, and 1493 under CC-BY-4.0.
- 206 sites are CC-BY-4.0. The other 6 are Tier 2 only: RU-Sam, RU-SkP, RU-Tks, RU-Vrk, SE-St1 and ZA-Kru.
- 86 sites are also in the AmeriFlux registry: 64 US, 20 CA and 2 BR.
- 74 of those 86 now have a newer AmeriFlux FLUXNET (ONEFlux) product, which uses the same variable definitions.
- Each site has one ZIP per product (FULLSET or SUBSET), with versions "1-4" or "2-4" from the February 2020 release.
  - The FULLSET ZIP holds FULLSET at HH or HR, DD, WW, MM and YY, plus ERAI at the same resolutions (1989-2014), AUXMETEO and AUXNEE.
  - The SUBSET ZIP holds SUBSET at the same resolutions plus AUXMETEO and AUXNEE, but no ERAI.
  - 201 sites are half-hourly (HH) and 11 are hourly (HR).
- Total sizes are about 13.6 GB for FULLSET and 3.9 GB for SUBSET.

**Mirrors.**
- I found no official anonymous mirror on Zenodo, Google Earth Engine, AWS Open Data or ICOS.
- AWS's nasa-fluxnet entry holds only older ORNL datasets, such as Marconi.
- ICOS hosts FLUXNET2015-format files only for European Drought-2018 and Warm Winter 2020 sites, with no US or CA sites.
- Zenodo has only derived datasets. Zenodo's own API returned 403 to me, so I checked it through DataCite.
- **Unofficial copy (should not be used):** an openly indexed, undocumented directory on ftp.fluxdata.org (/.fluxnet_downloads_67934/paper_test/) lists all 424 FLUXNET2015 ZIPs and two manifests. I read only the directory index and the manifest CSVs, and downloaded no data. Using it would bypass the intended-use form, so an MCP server must not rely on it unless FLUXNET says so in writing.

**What an MCP server can do for FLUXNET2015.**
- Discovery, availability, licensing and tier rules, variable and QC semantics, DOIs and citations: all programmatic and anonymous.
- Parsing and querying FLUXNET2015 ZIPs or CSVs that the user downloaded through the web form.
- Pointing AmeriFlux users to the newer AmeriFlux FLUXNET product through the Shuttle or AmeriFlux API (these require POST and user identity, so the user must opt in).

**What it cannot do.** It cannot fetch FLUXNET2015 data files itself through any documented anonymous path.

IMPLICATIONS:
- For FLUXNET2015, scope the MCP as a metadata, catalog and local-reader server, not a downloader. There is no documented anonymous data endpoint, and the official route is a login-gated web form that collects an intended-use statement for site PIs.
- Tools that can work anonymously over GET: fluxnet2015_list_sites (amfcdn /api/v1/site_display/FLUXNET/FLUXNET2015, filterable by country, IGBP, lat/lon bounding box and tier); fluxnet2015_get_availability (/api/v1/data_availability/FLUXNET/FLUXNET2015/{CCBY4.0|TIER2}, with path values validated to exactly those two strings); fluxnet2015_get_site (merge the site record, the fluxnet.org/sites/siteinfo/<ID> link and the DataCite DOI); fluxnet2015_get_citation (Pastorello 2020 .bib/.ris plus per-site DOI); fluxnet2015_describe_variable and fluxnet2015_list_variables (from the bundled official variable_codes_{FULLSET,SUBSET}_20200504.csv).
- Bundle the two variable-dictionary CSVs (68 KB and 19 KB, last modified 2020-05-05) and a snapshot of the site JSON as static MCP resources, with a refresh check against Last-Modified or ETag. FLUXNET2015 is frozen (last data change February 2020), so long cache TTLs are safe.
- Encode tier logic in a policy helper. Six sites are Tier 2 only (RU-Sam, RU-SkP, RU-Tks, RU-Vrk, SE-St1, ZA-Kru). A mixed selection makes everything Tier 2. Return attribution requirements with every data-related response.
- Download tool: return the official instructions and URL (fluxnet.org/data/download-historical-data/, which needs an AmeriFlux/FLUXNET account) rather than fetching. Never automate the login form, store credentials or submit intended-use text for the user. Do NOT use the undocumented ftp.fluxdata.org/.fluxnet_downloads_67934/paper_test/ directory unless FLUXNET (support@fluxnet.org) confirms in writing that it is sanctioned.
- Local reader tools that work on user-supplied ZIPs or CSVs: parse filenames with a regex for FLX_<CC-SSS>_FLUXNET2015_<GROUPING>[_<RES>]_<YYYY-YYYY>_<n-n>.(csv|zip), where GROUPING is FULLSET, SUBSET, ERAI, AUXMETEO or AUXNEE and RES is HH, HR, DD, WW, MM or YY; select columns by name, never by position; convert -9999 to null; parse TIMESTAMP_START/END for HH, HR and WW and a single TIMESTAMP for DD, MM and YY; and keep times in local standard time, with the UTC offset taken from site metadata.
- Handle HH vs HR transparently. 11 sites ship HR instead of HH (AU-Tum, BR-Sa1, SJ-Blv, US-Cop, US-Ha1, US-MMS, US-Ne1, US-Ne2, US-Ne3, US-PFa, US-UMB). ERAI files cover 1989-2014 regardless of the site's flux years, and ERAI appears only in FULLSET ZIPs.
- Add QC-aware helpers. At HH, filter on *_QC in {0,1} for measured or good gapfill. For consolidated _F met, QC 2 means ERA-downscaled. At DD to YY, QC is a 0-1 fraction, so expose a min_qc_fraction parameter. Default to the quick-start variables NEE_VUT_REF, GPP_NT_VUT_REF and GPP_DT_VUT_REF, RECO_*, LE_F_MDS, H_F_MDS and LE_CORR/H_CORR.
- Size planning: FULLSET HH CSVs can be over 250 MB uncompressed (US-Ha1 HR is 266 MB), and all of FULLSET is about 13.6 GB in ZIPs. Stream from inside the ZIP, use DuckDB or Arrow for column projection and time-window filters, and return summaries or paged rows rather than whole tables.
- For AmeriFlux-focused users, add a 'newer data' bridge. 74 of the 86 AmeriFlux FLUXNET2015 sites have the newer AmeriFlux FLUXNET (ONEFlux) product with identical variable semantics. Surface this through the anonymous GET /api/v2/site_info_display/AmeriFlux (grp_publish_fluxnet years and doi.FLUXNET). Any actual download through the Shuttle or AmeriFlux API needs POST plus user identity, so it should be an explicit, user-configured, opt-in tool that sets user_name and user_email from the user's own configuration and never defaults them.
- Reuse a single filename parser for both naming generations: the legacy FLX_*_FLUXNET2015_* and the Shuttle's <NET>_<SITE>_FLUXNET_<YYYY-YYYY>_v<x.y>_r<n>.zip. Then the same local reader handles FLUXNET2015, AmeriFlux FLUXNET and Shuttle archives.
- DOI resolution: use the DataCite REST API (api.datacite.org/dois?query=... under prefix 10.18140/FLX, 212 FLUXNET2015 DOIs) and/or the OSTI XML API for per-site citation metadata, because the fluxnet.org DOI landing page is client-side AngularJS.

CORRECTIONS:
- The shuttle filename regex does not limit names to 'ONEFlux v1.3+'. It accepts any v<N>[.<M>]_r<N> (for example v1.2_r2 and v3_r7 in its own docs and tests) and is matched case-insensitively. What it excludes is FLUXNET2015-style names (FLX_<SITE>_FLUXNET2015_FULLSET_<yyyy>-<yyyy>_beta-3.zip).
- Neither neon-mcp nor edi-mcp ships a server.json today (both paths are missing). edi-mcp DESIGN D11 plans one and states 'None of the sibling servers has one'. ameriflux-mcp would be among the first to ship one, not copying an existing file.
- The fluxnet R package's environment variables are AMERIFLUX_USER_NAME, AMERIFLUX_USER_EMAIL, AMERIFLUX_INTENDED_USE and AMERIFLUX_DESCRIPTION. AMERIFLUX_USER_ID is not one of them. If the goal is name parity, adopt USER_NAME/DESCRIPTION. user_id is a separate AmeriFlux account name that only the v1 data_download (amerifluxr) path needs.
- fluxnet/shuttle releases go back to 0.1.0 (2025-10-07), not 0.2.0.
- The fluxnet R package lives at EcosystemEcologyLab/fluxnet-package (main is at 0.6.0.9000). GitHub reports its licence as NOASSERTION, although DESCRIPTION says MIT. ONEFlux's GitHub SPDX is also NOASSERTION.
- The implication that FLUXNET2015 is 'not served' needs qualifying. ICOS SPARQL lists 22 current FLX_*_FLUXNET2015_FULLSET_*_beta-3.zip archives, for non-US/CA sites only, so some FLUXNET2015-format archives can be discovered anonymously, even though the shuttle regex would reject those names.
MISSED:
- v1 data_availability/AmeriFlux/<product>/<policy> always returns all 856 sites as a list. The policy segment changes only which sites have non-empty publish_years: FLUXNET/CCBY4.0 has 407 with years, FLUXNET/LEGACY 0, BASE-BADM/CCBY4.0 533, BASE-BADM/LEGACY 610. Tools must filter on non-empty publish_years and must not treat list length as availability. Observed via curl plus a python count.
- site_availability BIF lists are a different size from the catalog: CCBY4.0 has 674 entries and LEGACY 843 (LEGACY looks like a superset, i.e. all sites usable under the Legacy policy).
- The 'US AmeriFlux' catalog is Americas-wide. By country it has USA 695, Canada 93, Brazil 23, Mexico 16, Argentina 7, Peru 6, Chile 5, Costa Rica 5, and so on. Site status is Active 562 and Inactive 294. A server scoped to 'US' needs a country filter, or should describe itself as Americas-wide.
- The v2 site_info_display response is wrapped as {"values": [...]}, not a bare list. v1 endpoints return bare lists: site_availability returns [[id,name],...] and data_availability returns [{SITE_ID,URL,publish_years}].
- Shuttle's AmeriFlux plugin selects only sites with truthy grp_publish_fluxnet and silently skips any site whose citations/FLUXNET POST returns no citation (ameriflux.py lines 164 and 397-400). A port should surface those skips rather than drop them.
- The log POST sends intended_use as the lowercased enum name (synthesis, model, remote_sensing, other_research, education, other) from codes 1-6, and defaults to SYNTHESIS for unknown codes. The default Referer is 'local_shuttle' (core/config.py:32), which a third-party tool should not reuse without asking AMP.
- Site records carry three per-site URL fields (url, url_ameriflux, url_fluxnet), plus tower_dates, dom_dist_mgmt, flux_measurements_variables and base_variables, so per-site variable lists may be available without the 6.5 MB availability CSV. Their contents were not inspected.
- 2703 team-member entries in the public v2 catalog carry non-empty email addresses, which strengthens the case for redacting them by default.
- The ICOS SPARQL listing includes 22 FLUXNET2015 beta-3 archives under the FLX_ prefix (e.g. FLX_SE-Lnn_FLUXNET2015_FULLSET_2014-2018_beta-3.zip). These follow the legacy naming that the shuttle regex rejects, so a parser needs both patterns.
